# 无限画布与工作流功能状态

更新时间：2026-08-05

## 已完成

### 无限画布

- 图片拖入、批量本地上传和资产库选取。
- 上传文件写入 `AssetItem`，画布不再依赖模拟图片生成。
- 画布项目创建、打开、重命名、删除和自动保存。
- 图片可在任意自由坐标拖拽和四角等比缩放，移动与缩放支持撤销/重做。
- 图片自由坐标、层级、尺寸与视口快照持久化，刷新或切换项目后可恢复。
- 快照已升级到 schema v2；旧版网格快照会在读取时无损迁移为自由坐标。
- 自动保存携带版本 ID 与更新时间；旧标签页保存过期内容时返回 409 冲突，不再静默覆盖新内容。
- AI 生成结果可直接加入画布。

无限画布项目复用 `WorkflowDefinition` / `WorkflowDefinitionVersion` 存储，场景为 `INFINITE_CANVAS`，与可视化工作流数据相互隔离。

### 可视化工作流

- 节点拖拽、缩放和平移、连线、小地图、复制粘贴。
- 连线时校验端点、自连接、重复连接和循环依赖。
- 撤销/重做；一次模板插入只形成一个历史操作。
- 工作流列表、自动保存和版本快照。
- 历史版本回滚：回滚会创建一个新的草稿版本，不覆盖既有历史。
- 整图运行：运行前校验图结构，由服务端按拓扑依赖顺序串行执行 `llmConfig`、`imageConfig`。
- 页面关闭不会停止已经提交的服务端工作流；重新打开后会继续轮询运行记录并回填文本、图片结果。
- 运行中可停止：立即终止后续节点调度，并请求停止当前 LLM 或图片生成任务。
- 失败或服务重启中断的运行支持“从失败节点重试”，已经完成的节点不会重复计费执行。
- LLM 输出可作为图片或视频提示词；图片和视频生成会复用模板中已有的结果节点。
- 每次整图运行会创建服务端 `WorkflowRun`，每个可执行节点对应一条 `WorkflowNodeRun`。
- 节点开始、完成、失败、停止及整图完成状态会持续落库，并关联可用的 `GenerationRecord`。
- 重新打开工作流后可在“运行记录”查看上次运行状态、节点结果、错误信息和生成链接。

## 运行前置条件

整图运行依赖后台已经配置并启用对应的厂商与模型：

- `llmConfig`：至少一个可用对话模型。
- `imageConfig`：至少一个可用图片模型。
- `videoConfig`：单节点手动生成需要至少一个可用视频模型及其任务查询接口；整图服务端运行暂不支持视频节点。

未配置 API 密钥、模型或对象存储时，画布编辑、保存和版本管理仍可使用，但真实 AI 生成会返回明确错误。

## 当前边界

- 当前服务端调度器由单个 Node 服务进程承载，不是 Redis/BullMQ 等独立分布式队列；页面关闭不影响运行，但服务进程重启会把运行标记为中断，需要手动点击重试。
- 服务端整图运行暂不支持 `videoConfig`，避免把仍依赖浏览器 FormData 提交与轮询的视频链路误报为后台续跑。
- 发生自动保存冲突后会保留当前页面内容并提示重新打开；当前尚未提供自动合并两个版本的能力。
- 视频厂商没有统一的远端取消协议；停止工作流会中止本地请求与轮询，但已经提交给第三方的视频任务可能继续在远端运行。
- 输出节点保存的是结果 URL；外部 URL 的长期有效性取决于实际存储配置。
- 版本回滚只恢复画布定义与运行配置，不撤销已经产生的上游计费或远端生成任务。

## 本地验收

```bash
pnpm prisma:migrate:deploy:local
pnpm prisma:generate
pnpm type-check
pnpm test:scripts
pnpm exec tsx --env-file=.env.development scripts/tests/test-workflow-runs-integration.mjs
pnpm build
```

页面验收建议：

1. 在无限画布新建项目，上传两张图片，将图片拖到非网格位置并从左上角缩放；测试撤销/重做后刷新页面，确认自由坐标、尺寸和视口恢复。
2. 插入“文生图基础”模板，确认一次撤销可以完整移除该模板，一次重做可以恢复。
3. 尝试自连接、重复连线和造成循环的连线，确认操作被拒绝并显示原因。
4. 配置可用模型后点击“运行工作流”，关闭页面再重新打开，确认文本/图片节点继续按依赖顺序执行并复用已有结果节点。
5. 打开工作流历史版本并回滚，确认系统新增一个草稿版本，原历史版本仍保留。
